# ORD 조합 도우미 역설계 및 재기획

> 1차 구현 범위는 `docs/v1-scope.md`를 기준으로 한다. 아래 문서는 원본 기능 역설계와 장기 아이디어를 포함하므로, 로그인·저장·공유·메모 등 V1 제외 기능도 현황 설명에 남아 있다.

## 조사 기준

- 조사 화면: `https://ordsearch.net/mix/helper`
- 2026-07-19 Chrome에서 렌더링된 공개 화면 기준
- 화면에 입력 버튼 311개가 있으며, 이 중 310개는 고유 ID가 있는 유닛/재료이고 1개는 ID 없는 `흔함선택위습` 입력 도구임
- 수집된 데이터는 새 서비스의 초기 기준 데이터로 고정하며 원본 사이트와 자동 동기화하지 않음

## 현재 기능

### 보유 유닛 입력과 계산

- 등급별 유닛 목록에서 클릭하여 보유 수량 증가, 감소 버튼으로 차감
- 흔함 유닛 단축키: Q/W/E/R/A/S/D/F/G, 선택위습 V
- Shift+입력/클릭으로 감소, 전체 초기화 T, 메모 X, 되돌리기 Z
- 현재 보유 등급 요약 및 선택된 유닛 아이콘 표시
- 상위 유닛의 조합 재료와 현재 재고를 대조해 제작 가능 여부·부족 재료 계산
- 목재·골드 같은 기타 재료를 계산에 포함하는 옵션
- 특정 재료 또는 등급을 계산에서 제외하는 체크 기능
- 부족한 최하위 재료 수량 표시 임계값, 제작률 50% 미만 숨김 옵션

### 조합 탐색

- 등급별 목록: 흔함, 안흔함, 특별함, 희귀함, 전설적인, 히든조합, 왜곡됨, 랜덤전용, 변화된, 세라핌, 제한됨, 초월함, 신비함, 불멸의, 영원한, 기타, 특수함, 기록지침, 연구소, 아이템
- 유닛별 조합 재료 툴팁
- 상위/하위 조합 탐색용 버튼과 캐릭터 상세 페이지 연결
- 조합한 유닛만 모아 보는 기능
- 도우미에 없는 유닛을 별도로 추가
- 유닛 수정 모드와 조합 실행 취소

### 필터와 표시

- 공격력/공격속도 버프, 스턴, 방어·마방 감소, 보스 특화, 체력·마나 회복 등 25개 스킬 분류 필터
- 유닛 툴팁에 특수능력 표시 여부
- 이름순 정렬 및 등급 섹션 접기/펼치기
- 낮은 제작 진행률 결과 숨김

### 상태 보존과 공유

- SAVE / LOAD로 도우미 상태 저장·복원
- 현재 선택 유닛을 캐릭터 ID가 포함된 URL로 덱 화면에 전달하는 흐름
- 로그인 기반 클리어 저장·공개 클리어 탐색 기능은 전역 메뉴에 분리

## 확인된 원본 데이터 계약

각 캐릭터 행에는 다음 값이 렌더링되어 있다.

- `data-unit-id`: 캐릭터 고유 ID
- `data-origin-name`: 이름
- `data-level`, `data-level-text`: 등급 코드와 표시명
- `data-mates`: 직접 조합 재료 캐릭터 ID 목록
- `data-add-count`: 한 번 입력할 때 증가량
- `data-hotkey`: 단축키
- `data-* = Y/N`: 25개 스킬 태그
- tooltip HTML: 재료 설명, 특수 조건·설명

## 새 서비스 제안

핵심 경험을 **“지금 가진 유닛을 빠르게 입력하면, 만들 수 있는 최선의 조합을 우선순위로 보여준다”**로 좁힌다.

### 화면 구조

1. 왼쪽: 보유 유닛 입력 패널 — 현재 방식처럼 등급별 전체 목록을 한 페이지에 밀도 있게 배치하고 흔함은 고정 키패드로 제공
2. 가운데: 추천 조합 카드 — 제작 가능, 1개 부족, 장기 목표 순으로 분리
3. 오른쪽: 선택 조합의 재료 트리 — 보유/부족/제외 재료를 색으로 구분
4. 상단: 스킬 태그 다중 선택, 목표 등급, 제외 유닛, 정렬 기준
5. 모바일: 입력 → 추천 → 재료 트리를 3개 탭으로 전환

### 기존 대비 개선점

- 등급별 전체 유닛을 항상 한 페이지에 렌더링한다. 게임 중 별도 탐색 없이 모든 요소와 수량을 동시에 확인할 수 있어야 한다.
- 가상 스크롤, 페이지네이션, 등급 탭 전환처럼 목록 일부를 DOM이나 화면에서 제거하는 방식은 사용하지 않는다.
- 현재 사이트의 조밀한 다단 등급 테이블 구조를 유지하되 행 높이, 여백, 글자 크기와 열 배치를 다듬어 전체 페이지 스크롤 이동을 최소화한다.
- 검색은 목록을 대체하지 않는 보조 기능으로만 제공하며, 검색 후에도 전체 배치와 현재 입력 상태를 잃지 않게 강조·위치 이동 방식으로 동작한다.
- 단일 라디오 스킬 필터를 다중 태그 AND/OR 필터로 개선
- “제작률”뿐 아니라 부족 재료 수, 예상 경로 길이, 원하는 스킬 조합으로 정렬
- 조합 재료를 재귀 트리와 평탄화된 최하위 재료 명세 두 방식으로 표시
- 입력 실수를 줄이는 명시적 실행 취소/다시 실행과 변경 이력
- 로컬 자동 저장을 기본으로 하고 계정 로그인 시 기기 간 동기화
- 원본 설명 HTML을 그대로 노출하지 않고 구조화된 스킬·조건 필드로 정제

## 권장 MVP

1. 현재 확보한 초기 데이터를 DB 기준값으로 정리
2. 보유 유닛 입력/감소/초기화/undo
3. 재귀 조합 계산과 부족한 최하위 재료 계산
4. 등급·스킬·제작 가능성 필터
5. 로컬 저장 및 공유 가능한 덱 URL
6. 반응형 UI와 키보드 단축키

로그인, 커뮤니티, 공개 클리어 랭킹은 MVP 이후로 미룬다.

## DB 확장 방향

- `units`: 캐릭터 기본 정보와 등급
- `recipes`: 결과 유닛과 직접 재료, 수량
- `skills`, `unit_skills`: 스킬 사전과 다대다 태그
- `unit_aliases`: 검색용 별칭/초성/오타
- `unit_assets`: 이미지 URL, 해시, 라이선스·출처
- `recipe_conditions`: 골드·목재·확률·스토리 같은 비유닛 조건
- `decks`, `deck_units`: 사용자 저장 덱
- `user_preferences`: 필터, 제외 재료, 단축키, UI 설정

운영 DB는 PostgreSQL을 권장하고, 현재 SQLite 파일은 초기 프로토타입용으로 사용한다. 이후 데이터 변경은 원본 사이트 동기화가 아니라 프로젝트 DB를 직접 수정하는 방식으로 관리한다.
